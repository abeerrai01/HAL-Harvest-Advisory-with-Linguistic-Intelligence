🤖 AI/ML Models & Approach

1. Google Gemini 2.0 Flash - Crop Advisory & Recommendations

  • Purpose: Generate intelligent crop advisory recommendations based on NDVI, weather, soil data, and field conditions
  • Input: Field geometry, NDVI values, weather forecasts, soil health data, current crop information, language preference
  • Output: Comprehensive JSON with recommended crops, fertilizer guidance, irrigation plans, pest management, market insights
  • Features: Multi-language support (10+ Indian languages), context-aware recommendations, seasonal calendar generation
  • API Endpoint: generativelanguage.googleapis.com/v1/models/gemini-2.0-flash:generateContent

2. Google Gemini 2.0 Flash - Disease Chat & Q&A

  • Purpose: Conversational AI for answering farmer questions about detected plant diseases
  • Input: Disease label, user question, conversation history, field context, language
  • Output: Expert advice on diagnosis, immediate actions, organic solutions, prevention tips
  • Features: Context-aware responses, multi-turn conversations, organic-first recommendations

3. Google Gemini 2.0 Flash - Weather Advisory

  • Purpose: Generate dynamic weather-based agricultural advisories
  • Input: Current weather, 48-hour forecast, 7-day forecast, location coordinates, language
  • Output: Risk summaries, irrigation recommendations, crop protection advice, action items
  • Features: Real-time risk assessment, proactive recommendations, multi-language support

4. Custom Pest/Disease Classification Model (Hugging Face)

  • Purpose: Classify plant diseases and pests from crop images
  • Model Location: theabeerrai-pest-hal.hf.space
  • Input: Crop image (JPEG/PNG), language preference
  • Output: Disease name, confidence score, detailed report, other possible diseases
  • Features: Multi-disease detection, confidence scoring, detailed pathology reports

5. Google Speech-to-Text API - Voice Input

  • Purpose: Convert farmer voice queries to text for voice assistant
  • Input: Audio file (WAV, M4A, FLAC, OGG), language code
  • Output: Transcribed text, confidence score
  • Features: Enhanced model for noise reduction, automatic punctuation, multi-language support (10+ Indian languages)
  • Supported Languages: English, Hindi, Marathi, Tamil, Telugu, Kannada, Malayalam, Gujarati, Punjabi, Bengali, Odia

AI/ML Integration Strategy

Hybrid Approach: The system uses a combination of:

  • Pre-trained Models: Google Gemini for natural language understanding and generation
  • Custom Models: Hugging Face-based pest/disease classification model
  • Rule-based Logic: NDVI calculations, anomaly detection, health scoring
  • Data Fusion: Combining satellite imagery, weather data, soil data, and historical patterns

Data Flow Architecture

1. User Authentication
App → Firebase Auth → User Session → Firestore User Document
↓
2. Field Setup
User draws field on map → 4 GPS coordinates → POST /api/v1/fields → Firestore: users/{uid}/fields/{field_name}
↓
3. Crop Health Analysis Request
User taps "Analyze Field" → POST /api/v1/jobs → Firestore: jobs/{job_id} (status: PENDING)
↓
4. Worker Processing
Worker polls Firestore → Finds PENDING job → Updates to PROCESSING → Fetches field geometry
↓
5. Parallel Data Collection
Worker → Sentinel Hub API (NDVI) + OpenWeatherMap API (Weather) + SoilGrids API (Soil) → Processes data
↓
6. AI Recommendation Generation
Processed data → Google Gemini API → Comprehensive crop advisory JSON → Firestore: reports/{job_id}
↓
7. Job Completion
Worker updates job status to COMPLETED → App polls status → Displays report to user

Pest/Disease Detection Flow

1. Image Capture
User captures crop image → Expo Image Picker → Image file/URI
↓
2. Image Upload
App → POST /api/v1/pest-disease/classify (multipart/form-data) → Backend receives image
↓
3. Disease Classification
Backend → Hugging Face API (theabeerrai-pest-hal.hf.space) → Disease report with confidence scores
↓
4. AI Recommendation
Disease report → POST /api/v1/pd-recommendation → Google Gemini → Treatment recommendations
↓
5. Conversational Q&A
User asks question → POST /api/v1/disease-chat → Google Gemini → Expert answer
↓
6. History Storage
All detections → Firestore: users/{uid}/pd_history → User can view past detections

📋 Methodology & Implementation Process

Development Methodology

Phase 1: Requirements & Planning

Identified farmer needs: crop health monitoring, pest/disease detection, weather advisories, market prices, government schemes. Defined user personas and use cases.

Phase 2: Architecture Design

Designed microservices architecture: Mobile app (React Native), Backend API (Express.js), Worker process (Node.js), External API integrations. Defined data models and API contracts.

Phase 3: Core Infrastructure

Set up Firebase project (Auth, Firestore), configured development environment, implemented authentication flow, created base API structure with Express.js.

Phase 4: Field Management

Implemented map-based field drawing (react-native-maps), GPS coordinate capture, field storage in Firestore, field selection and management UI.

Phase 5: Satellite Data Integration

Integrated Sentinel Hub and Planet Labs APIs, implemented NDVI calculation pipeline, created worker process for asynchronous job processing, built NDVI visualization.

Phase 6: Weather Integration

Integrated OpenWeatherMap and WeatherAPI.com, implemented weather caching, built weather advisory generation with AI, created forecast visualization.

Phase 7: AI/ML Integration

Integrated Google Gemini for crop advisory, implemented Hugging Face pest/disease model, added Google Speech-to-Text, built conversational AI for disease Q&A.

Phase 8: Image Processing

Implemented image upload with Multer, integrated pest/disease classification API, built image preprocessing pipeline, created result visualization.

Phase 9: Multi-language Support

Implemented i18n system, integrated Google Translate API, added language selection UI, configured AI models for multi-language responses.

Phase 10: Testing & Optimization

Conducted end-to-end testing, optimized API response times, implemented error handling and retry logic, added caching mechanisms, performance tuning.

Phase 11: Deployment

Deployed backend to Vercel, configured environment variables, set up worker process, published mobile app to app stores, configured production Firebase.

Phase 12: Monitoring & Maintenance

Implemented logging and error tracking, set up API monitoring, created user feedback mechanisms, continuous improvement based on usage data.

💰 Mandi Price (Market Prices) Feature

Overview

The Mandi Price feature provides real-time and historical market prices for agricultural commodities, helping farmers make informed decisions about when and where to sell their produce for maximum profit.

Data Source

  • Data.gov.in API (Government of India)
  • Uttarakhand Mandi Price API (Hugging Face)
  • Real-time daily price updates
  • Historical price data (last 10-30 records)

Key Features

  • Current market prices (modal, min, max)
  • Price trend visualization
  • Predicted optimal sell date
  • Price change percentage
  • Market-wise price comparison

AI Prediction

  • Linear regression for price forecasting
  • 7-day price prediction
  • Optimal sell date recommendation
  • Market volatility analysis

Mandi Price Flow

1. User Opens Market Prices Screen
User navigates to Market Prices → Selects crop and market (mandi) → App displays available crops
↓
2. Fetch Market Metadata
App → GET /api/v1/market-meta → Returns available states, districts, markets for selected commodity
↓
3. Request Market Prices
App → GET /api/v1/market-prices?commodity={crop}&state={state}&district={district}&market={mandi}
↓
4. Backend Processing
Backend → Data.gov.in API → Progressive filter relaxation (state+district+market → commodity only) → Returns best_today and last10 prices
↓
5. Price Prediction
App → GET /api/v1/market-prices/predict → Backend calculates linear regression → Predicts optimal sell date (next 7 days)
↓
6. Display Results
App displays: Current price, price range, price change %, historical chart, predicted sell date, market influencers

🌾 PAYAL - Precision Agriculture And Yield Advisory with Linguistic Intelligence

PAYAL is an intelligent multilingual farming assistant that provides personalized agricultural advice through both text chat and voice interactions. It combines AI-powered natural language understanding with domain-specific agricultural knowledge.

PAYAL Capabilities

  • Crop Advice: Get crop recommendations based on location, soil conditions, and season
  • Fertilizer Advice: Learn about NPK requirements and fertilizer recommendations for specific crops
  • Soil Health: Get soil health diagnosis and improvement recommendations
  • Weather Forecast: Get weather forecasts and farming advice based on location
  • Pest Information: Learn about pest detection and control methods
  • Government Schemes: Get information about government schemes and subsidies

PAYAL 2.0 (Voice Assistant)

Intelligent Routing

PAYAL Flow

User opens Voice Assistant screen → Selects text chat or voice mode → PAYAL greets user
↓
2. Text Chat Flow (PAYAL 1.0)

↓
3. Voice Chat Flow (PAYAL 2.0)
User taps voice button → App → POST /start → PAYAL 2.0 API → Returns LiveKit credentials (URL, token, roomName)

↓
6. Response Display
PAYAL response received → Displayed as text (chat) or played as audio (voice) → Conversation history saved → User can continue conversation

PAYAL API Endpoints

  • POST /chat/weather - Weather-based farming advice

Solutions for Low/No Network Regions

Offline-First Architecture

Implement local database (SQLite/Realm) for offline storage. Cache all critical data (crop advisory, market prices, pest info) locally. Sync when connectivity available.

Data Compression

Compress all API responses, images, and data transfers. Use efficient data formats (Protocol Buffers, MessagePack). Minimize bandwidth usage.

Progressive Data Loading

Load essential data first, background sync for detailed information. Prioritize critical features (weather alerts, pest warnings) over nice-to-have features.

Mesh Network Support

Enable device-to-device communication via Bluetooth/WiFi Direct. Farmers can share data with nearby devices without internet. Community data sharing.

Edge Computing

Deploy edge servers in rural areas. Local processing reduces latency and bandwidth. Cache frequently accessed data at edge locations.

Satellite Internet Integration

Partner with satellite internet providers (Starlink, OneWeb) for remote areas. Provide subsidized connectivity for farmers.
